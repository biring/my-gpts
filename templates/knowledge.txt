=== TEMPLATE NOTES =================================================

Delete this block when generating a knowledge file.

Purpose: A knowledge file holds domain rules, examples, and edge cases that would push the Instructions field over its character limit. It explains and exemplifies; it does not replace or restate the Instructions field's authority.

Scope: This template is for ONE knowledge file that supports ONE instructions.txt.

Curly braces mark an authoring instruction or hint for the template author, and are removed or replaced when generating a knowledge file.

Angle brackets mark a value the GPT itself substitutes at generation time, and stay in the final knowledge file exactly as written.

Core sections {CORE} apply to every knowledge file. Optional sections {OPTIONAL} apply only in specific situations (noted inline); delete the section if it does not apply.

SECTION ORDER AND WHY:
  1. PURPOSE                               {CORE}     - context: what, why
  2. SCOPE                                 {CORE}     - context: when
  3. RULES                                 {CORE}     - the requirements
  4. NAMING CONVENTIONS                    {OPTIONAL} - a specific sub-rule
  5. EXPLICIT NON-GOALS                    {CORE}     - the anti-rules
  6. AMBIGUITY & CLARIFICATION POLICY      {OPTIONAL} - resolving judgment calls
  7. STABLE-CONTENT CRITERIA               {OPTIONAL} - gate before generating
  8. EXAMPLE 1+                            {CORE}     - what compliant output looks like
  9. VALIDATION & SELF-CHECKS              {CORE}     - final self-check

Additional sections may be added beyond this list when a particular knowledge file needs one not covered here.

FORMATTING HIERARCHY (plain text, no markdown):

Levels:

  SECTION      — top level, ALL CAPS, no prefix. Content always starts on a new line below the heading.
  Label:       — sub-level under a section, title case + colon. Plain ("Label:") or numbered ("1. Label:") when the section has multiple ordered/named groups. Content starts inline on the same line as the label, unless that content is itself a list — in which case it drops to the lines below instead.

Numbering & Bullets:

  - item       — bulleted, used when the items have no required order.
  1. item      — numbered, used when sequence or order matters.

Spacing Rules:

  2 blank lines above every SECTION heading.
  1 blank line above every Label:, plain or numbered.
  1 blank line above any bulleted or numbered list, wherever it appears.

Not Allowed:

  No **, backticks, or a leading "> " used as a blockquote prefix, anywhere in the body. This does not forbid square brackets (used informally, e.g. an illustrative placeholder inside an example — not a formal convention) or angle brackets (the runtime-marker convention) — neither is markdown. Only the glyphs defined above (SECTION, Label:, - item, numbered item) plus curly-brace and angle-bracket notation are permitted.

Line Wrapping:

  Do not manually break a sentence or paragraph across multiple lines. Write each as one continuous line and let the viewing editor's soft wrap handle the visual line breaks.

EXAMPLE may be numbered (EXAMPLE 1, EXAMPLE 2, ...) and repeated as needed. Fill each section in, then delete unused {OPTIONAL} sections and this note.
