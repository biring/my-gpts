Delete this block when generating GPT instructions

Single-purpose GPT: one set of inputs per run, one output with optional report.

CORE sections are required in every GPT.
OPTIONAL sections are include only when the noted condition applies; delete the section otherwise.

FORMATTING HIERARCHY (plain text, no markdown):
  SECTION NAME     — top level, ALL CAPS, no prefix
  Label:           — sub-label, title case + colon
  - item           — list item under a label or section
  # Subsection:    — named subsection; use only when a section has three or
  - item             more named groups; one or two groups use plain Label: instead
  <note> — authoring instruction or hint; remove entirely when generating GPT instructions

SPACING RULES:
  2 blank lines before every SECTION NAME
  No blank line between a section heading and its first content
  1 blank line before each # subsection
  No blank line between a Label: or # Subsection: and its dash items
  1 blank line between plain Labels: within the same section

CHARACTER COUNT CHECK:
ChatGPT enforces a hard limit on GPT instructions. Keep the final file under 7,900 characters after deleting the template notes block and all <...> content.

To check: cat instructions.txt | wc -c

If over 7,900 characters: rewrite and compress the prose to say the same thing in fewer words. Preserve the intelligence, meaning, and intent of every section. Do not drop sections or weaken constraints.
If compression alone cannot get under 7,900 characters, extract sections to knowledge-<section_name>.txt in this priority order: OUTPUT REPORT first, then OUTPUT CONTRACT (Output Body detail), then INPUT REQUIREMENTS. Each is self-contained reference/mechanical detail with no control-flow logic, so extracting them rarely weakens the GPT.

Do not extract MODES OF OPERATION. It gates whether the GPT is allowed to generate output at all, and knowledge files are retrieved semantically rather than guaranteed to be in context every turn — a missing gating rule risks premature generation, not just a formatting miss. If the file is still over budget after extracting the three sections above, compress remaining CORE sections further before considering any other section for extraction.

Replace each extracted section's content in instructions.txt with a pointer sentence: "See knowledge-<section_name>.txt." Add a short descriptive phrase (e.g. "for accepted formats and X") only when more than one knowledge file could plausibly cover the topic and the reader needs to know which one to open; otherwise the bare pointer is sufficient — the section heading already scopes the topic. Use the knowledge.txt template to structure the new file and add sections as needed to fully cover the moved content.
