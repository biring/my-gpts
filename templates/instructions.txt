FORMATTING HIERARCHY (plain text, no markdown):

Levels:

  SECTION      — top level, ALL CAPS, no prefix. Content always starts on a new line below the heading.
  Label:       — sub-level under a section, title case + colon. Plain ("Label:") or numbered ("1. Label:") when the section has multiple ordered/named groups. Content starts inline on the same line as the label, unless that content is itself a list — in which case it drops to the lines below instead.

Numbering & Bullets:

  - item       — bulleted, used when the items have no required order.
  1. item      — numbered, used when sequence or order matters.

Spacing Rules:

  2 blank lines above every SECTION heading.
  1 blank line above every Label:, plain or numbered.
  1 blank line above any bulleted or numbered list, wherever it appears.

Not Allowed:

  No **, backticks, or a leading "> " used as a blockquote prefix, anywhere in the body. This does not forbid square brackets (used informally, e.g. a literal suffix or an illustrative placeholder inside an example — not a formal convention) or angle brackets (the runtime-marker convention) — neither is markdown. Only the glyphs defined above (SECTION, Label:, - item, numbered item) plus curly-brace and angle-bracket notation are permitted.

Line Wrapping:

  Do not manually break a sentence or paragraph across multiple lines. Write each as one continuous line and let the viewing editor's soft wrap handle the visual line breaks.

CHARACTER COUNT CHECK:
ChatGPT enforces a hard limit on GPT instructions. Keep the final file under 7,900 characters after deleting the template notes block and all {...} content.

To check: cat instructions.txt | wc -c

If over 7,900 characters: rewrite and compress the prose to say the same thing in fewer words. Preserve the intelligence, meaning, and intent of every section. Do not drop sections or weaken constraints.
If compression alone cannot get under 7,900 characters, extract sections to a knowledge file as needed. Extracted content must follow this file naming convention: knowledge-{short_name}.txt, where short_name is a content-type category (e.g. input, output, reports, audit) rather than a literal section name — more than one related section can share the same category file. Leave a context brief behind (see below) so the extracted content stays usable even on a turn where the knowledge file isn't retrieved.

Replace each extracted section's content in instructions.txt with a brief context paragraph plus a pointer sentence naming the file, e.g. "See knowledge-{short_name}.txt." The brief exists for the GPT, not the reader: knowledge files are retrieved semantically and are not guaranteed to be in context every turn, so the brief must give the GPT enough to recognize when it needs that section's content and go retrieve the file — a brief that's too thin risks the file being missed or ignored exactly when it's needed. Use the knowledge.txt template to structure the new file and add sections as needed to fully cover the moved content.
