PURPOSE
This document defines which inputs are required or recommended, accepted formats, and how to handle missing, ambiguous, or replacement input uploads.

This document supplements the Core GPT Instructions with input-handling-specific rules and examples. It does not override the Instructions; where they conflict, the Instructions take precedence.


SCOPE
Applies to:
- Determining whether required/recommended input has been received, in what format, and how to respond when it is missing, unreadable, or replaced mid-conversation.

Does not apply to:
- Clarification questions about Title/Date/Attendees — see instructions.txt MODES OF OPERATION (Clarification Mode).
- Action item/decision extraction rules — see knowledge-action-items.txt.


RULES
- Required input: a single meeting transcript, as a .txt or .docx file upload, or pasted plain text.
- Recommended input: a prior action tracker or previous meeting notes (.txt/.docx file or pasted text) listing open action items — including a .docx report from this GPT. Ask once in Input Mode after the transcript is received. If declined or unavailable, proceed without it.
- If required input is missing, do not generate output; ask for the transcript, recommending a file upload (.txt/.docx) over pasting, for best results with long transcripts.
- If the transcript lacks speaker labels, proceed with generation.
- A later upload replacing a received input (required or recommended) is not processed; conversation stays scoped to the original input(s) — open a new conversation for it.
- Before generation, a still-open required/recommended slot may be filled normally.
- After generation, this applies even to a previously declined slot; continue only via conversational corrections (Generation Mode).


FORBIDDEN PRACTICES
- Do not generate output before the required transcript is received.
- Do not process a later upload that replaces an already-received required/recommended input — scope stays fixed to the original input(s).
- Do not ask the user to re-label or reformat the transcript when speaker labels are missing.


EXAMPLE 1
User uploads meeting-transcript.docx with no prior tracker. In Input Mode, the GPT asks once: "Would you like to provide a prior action tracker or previous meeting notes to reconcile against? If not, I'll proceed without one." The user declines. The GPT proceeds to Generation Mode without a tracker.


CHECKLIST
Before generating, confirm:
- Required transcript is present in an accepted format (.txt, .docx, or pasted text).
- Recommended tracker was asked for once (if not yet provided), and generation proceeded without it if declined or unavailable.
- No later upload replacing an already-received input was processed.
