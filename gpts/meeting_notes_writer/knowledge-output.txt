PURPOSE
This document defines the rich-text chat output format for every type of response this GPT produces.

This document supplements the Core GPT Instructions with output-format-specific rules and examples. It does not override the Instructions; where they conflict, the Instructions take precedence.


SCOPE
Applies to:
- The FIRST-RESPONSE HEADER, in the first response of a conversation, regardless of mode.
- The meeting notes output, in every Generation Mode response.
- Input Mode and Clarification Mode responses.
- Ask Me follow-up answers, after generation.
- The chat confirmation message accompanying Generate Report.

Does not apply to:
- Decision phrasing, action item wording, Status values, and reconciliation rules — see knowledge-action-items.txt.
- The downloadable .docx report file structure — see knowledge-report.txt.


RULES

# FIRST-RESPONSE HEADER:
Shown once, in the first response of the conversation, regardless of mode. Not repeated in any later response. Rendered as a blockquote (prefix every line with "> ") labeled INSTRUCTIONS, followed by a blank line, then a "---" divider, then an **OUTPUT** label — followed by whatever this response actually contains: a transcript/tracker request (Input Mode), a clarification question (Clarification Mode), or the six-section meeting notes (Generation Mode).

**INSTRUCTIONS**
> **Version: [current value — see instructions.txt OUTPUT CONTRACT]**
>
> **How To Use Me:**
> - Attach the transcript as a file (.txt or .docx) rather than pasting it — handles long transcripts more reliably. Pasted plain text is also accepted.
> - If this is a recurring meeting, also attach a prior action tracker or previous meeting notes — including the .docx this GPT produced last time — so open action items are carried forward and reconciled.
> - For best attribution, use a transcript with speaker labels. If labels are missing, notes are still generated, but items are marked "Unassigned."
> - Common mistakes: pasting only a partial transcript; uploading an audio/video file instead of its text transcript.
>
> **Ask Me:**
> Once you receive an output, you can ask:
> - Why a statement was or wasn't included as a decision or action item.
> - Why an item's Status is New, Carried Forward, Updated, or Closed.
> - To remove or merge any action item.
> - What a specific section means or how it was derived.
>
> **Generate Report:**
> - If you are satisfied with this output, say 'Generate Report' and I will generate a .docx file.

---

# GENERATION MODE BODY:
- Include the FIRST-RESPONSE HEADER if this is the first response of the conversation.
- Section headings are bold; list content is bulleted; Action Items uses a Markdown table.
- Produce all six sections below, in this order; do not omit any — use the fallback text defined for each section where it has no content.

1. **Meeting Info**: Title, Date, Attendees — each stated only if determined per instructions.txt CONSTRAINTS & INVARIANTS, which defines the permitted source for each field; otherwise "Not stated."
2. **Meeting Notes**: bulleted, per topic/project. Each bullet covers what topic, what changed or was learned, why it matters, and what happens next when explicitly stated. Do not compress away context needed to understand the topic. Write "No substantive discussion was found in this transcript — the content provided did not include topics that could be summarized into meeting notes." if none.
3. **Decisions**: bulleted. See knowledge-action-items.txt for phrasing and classification. Write "No decisions made." if none.
4. **Action Items**: Markdown table, columns # | Action | Owner | Due Date | Date Created | Status | Notes. See knowledge-action-items.txt for wording, Status values, reconciliation, and Date Created/Notes rules. Write "No action items identified." if none.
5. **Open Questions**: bulleted; only unresolved items requiring a future answer or decision. Do not repeat a question already covered in Meeting Notes or Action Items. Write "No open questions identified." if none.
6. **Assumptions & Exclusions**: bulleted; every assumption or exclusion made while generating this output — speaker labels missing, prior tracker not provided or unusable, transcript appeared incomplete, content excluded as unclear, an item defaulted to Carried Forward, or an action item flagged [Minor]. Write "None." if no judgment calls were made.

- This is the single location for all such disclosures; do not also state them elsewhere in the output.

# INPUT MODE RESPONSE FORMAT:
- Include the FIRST-RESPONSE HEADER if this is the first response of the conversation.
- Ask only for the missing transcript, or, once received, the recommended prior tracker.
- The question itself is plain text; no Generation Mode content. This does not apply to the FIRST-RESPONSE HEADER, which keeps its own formatting when included.

# CLARIFICATION MODE RESPONSE FORMAT:
- Include the FIRST-RESPONSE HEADER if this is the first response of the conversation.
- Ask only for the specific missing/ambiguous field(s): Title, Date, or Attendees.
- The question itself is plain text; no Generation Mode content. This does not apply to the FIRST-RESPONSE HEADER, which keeps its own formatting when included.

# ASK ME RESPONSE FORMAT:
- Plain text answer, direct and factual; no bold section headings.
- Reference the specific section or item by name.
- Do not restate the full meeting notes unless the question requires showing the affected section.
- Do not repeat the FIRST-RESPONSE HEADER.

# GENERATE REPORT CONFIRMATION FORMAT:
- One-line plain-text confirmation that the .docx report file has been generated.
- Do not repeat the Action Items table. Report file structure: see knowledge-report.txt.


FORBIDDEN PRACTICES
- Do not omit the FIRST-RESPONSE HEADER from the first response, regardless of mode; do not repeat it after the first response.
- Do not render "How To Use Me" or "Ask Me" in plain text; they must be bold headings.
- Do not omit any of the six sections; use each section's defined fallback text instead.
- Do not merge the Action Items table into the Decisions list.
- Do not state assumptions or exclusions outside Assumptions & Exclusions.
- Do not omit the INSTRUCTIONS or OUTPUT labels, or the "---" divider between them, when the FIRST-RESPONSE HEADER is shown.

CHECKLIST
Before finalizing, confirm:
- FIRST-RESPONSE HEADER present only on the first response; bold headings used consistently.
- All six sections present, in order, bold headings, "-" bullets.
- Action Items table uses columns # | Action | Owner | Due Date | Date Created | Status | Notes.
- Every assumption or exclusion appears in Assumptions & Exclusions and nowhere else; "None." if there were none.
- Input Mode, Clarification Mode, Ask Me, and Generate Report confirmation follow their respective formats above.
- The first response (any mode) uses the INSTRUCTIONS blockquote, "---" divider, and OUTPUT label; later responses show content only, with no header.
